# EgoFlow App Scope

이 문서는 `ego-flow-app` 저장소의 범위와 샘플 구성을 정리한다.

## 1. 저장소 역할

`ego-flow-app`은 앱 계층 저장소다. Meta AI(DAT) glasses에 연결해 live preview를 보여주고, 사진을 찍고, live feed를 EgoFlow backend로 publish 한다. `v0.0.1` Record UI는 **RTMP/RTMPS 또는 HTTP-chunk** 중 하나를 선택한다.

본 저장소의 책임 범위:

- Meta glasses와 phone/app 연결 (DAT SDK)
- glasses live preview + phone-camera fallback 소스
- 사진 촬영/공유
- EgoFlow backend 로그인 및 repository 선택
- recording-session 라이프사이클: register → publish-ticket → publish → close-intent
- RTMP/RTMPS 또는 HTTP-chunk를 통한 지원 publish
- 향후 검증을 위해 보존한 dormant/experimental WHIP 구현 모듈
- app-side 설정, 인증, repository 선택

slab-append → Clone-server 트랙만 본 저장소에 없다. sibling fork(Clone Glasses)가 담당한다. 자세한 분기 사유는 [03. project_architecture.md §5](./03.%20project_architecture.md) 참고.

## 2. 트랙 구성

| 트랙 | `v0.0.1` 상태 | ingestType | 담당 |
| --- | --- | --- | --- |
| RTMP live (glasses → Android → MediaMTX) | 지원 | `MEDIAMTX` | 본 저장소 (`:transport-rtmp`) |
| HTTP-chunk live upload (fMP4 → EgoFlow backend) | 지원 | `HTTP` | 본 저장소 (`:transport-http`) |
| WHIP live (WebRTC → MediaMTX) | dormant/experimental, UI 선택 불가 | `MEDIAMTX` | 본 저장소 (`:transport-whip`) |
| slab-append → Clone server | 별도 프로젝트 | — | sibling fork: Clone Glasses |

세 구현 모듈은 같은 `Transport` seam과 `EgoFlowBackendClient` 제어면을 공유한다. WHIP 구현은 별도 ingest type이 아니라 MediaMTX ingest를 RTMP와 공유하며 publish 단계만 다르지만, 모듈 존재만으로 `v0.0.1` 지원 경로가 되지는 않는다.

## 3. 샘플 맵

| 경로 | 역할 | 상태 |
| --- | --- | --- |
| `samples/CameraAccessAndroid` | DAT 기반 Android live preview + 지원 RTMP/HTTP publish; dormant WHIP module | 현재 기준 구현 (server-integrated) |
| `samples/CameraAccess` | iOS DAT 샘플 (glasses/iPhone preview + photo, Gemini Live + OpenClaw 어시스턴트) | reference-only, work in progress — server flow 미연동 |

RTMP를 받는 MediaMTX 스택은 **외부 참조 스택**이며 더 이상 저장소에 vendoring 되지 않는다. dormant WHIP 구현도 같은 MediaMTX를 대상으로 작성되어 있다.

`CameraAccessAndroid`는 다섯 개의 Gradle 모듈로 분리되어 있다 (`:app`, `:core`, `:transport-rtmp`, `:transport-whip`, `:transport-http`). 자세한 모듈 경계는 [03. project_architecture.md §2](./03.%20project_architecture.md) 참고.

## 4. 기술 스택

### 4.1 Android (`CameraAccessAndroid`)

| 영역 | 구현 |
| --- | --- |
| Platform | Android (`compileSdk 35`, `minSdk 31`) |
| Language | Kotlin (`2.1.20`), AGP `8.6.0`, JDK 17 |
| Build | Gradle multi-module (`:app`, `:core`, `:transport-rtmp`, `:transport-whip`, `:transport-http`) |
| UI | Jetpack Compose, `compose-icons-lucide` 아이콘 |
| Glasses SDK | Meta Wearables DAT Android SDK (GitHub Packages, `read:packages` PAT 필요) |
| Transport seam | `:core`의 `Transport` 인터페이스 |
| Streaming | 지원: RTMP/RTMPS publish · HTTP fMP4 chunk 업로드; dormant: WHIP(WebRTC) 구현 |
| Backend HTTP | OkHttp (`EgoFlowBackendClient`: login/repositories/register/publish-ticket/close-intent/http-streams) |
| Encoding | MediaCodec (H.264/HEVC, `:core/encoder/VideoEncoder`) |

### 4.2 외부 ingest 스택

지원되는 RTMP 경로는 외부 MediaMTX host로 나간다. HTTP transport는 EgoFlow backend의 `/http-streams` 제어면으로 직접 업로드한다. 어느 쪽이든 앱의 backend base URL을 테스트 대상 host로 맞춘다. WHIP도 MediaMTX를 대상으로 구현되어 있지만 `v0.0.1` UI와 acceptance에서는 비활성이다.

## 5. 중요한 구분

- `CameraAccessAndroid`는 현재 기준 Android 구현이다. `v0.0.1`은 RTMP/RTMPS와 HTTP를 지원한다.
- `:transport-whip`은 소스와 테스트만 보존한 dormant/experimental 모듈이다. 향후 지원 전에는 UI 복원과 실기기 WebRTC/ICE E2E가 필요하다.
- RTMP ingest(MediaMTX)는 production EgoFlow server와 별개의 외부 스택이다.
- slab-append/Clone-server 트랙은 본 저장소에 없다. sibling fork(Clone Glasses)에서 진행된다.
