# EgoFlow App Scope

이 문서는 `ego-flow-app` 저장소의 범위와 샘플 구성을 정리한다.

## 1. 저장소 역할

`ego-flow-app`은 앱 계층 저장소다. Meta AI(DAT) glasses에 연결해 live preview를 보여주고, 사진을 찍고, live feed를 EgoFlow backend로 publish 한다. publish는 세 transport(**RTMP / WHIP / HTTP-chunk**) 중 Settings에서 고른 하나로 나간다.

본 저장소의 책임 범위:

- Meta glasses와 phone/app 연결 (DAT SDK)
- glasses live preview + phone-camera fallback 소스
- 사진 촬영/공유
- EgoFlow backend 로그인 및 repository 선택
- recording-session 라이프사이클: register → publish-ticket → publish → close-intent
- RTMP / WHIP / HTTP 세 transport로의 live publish
- app-side 설정, 인증, repository 선택

slab-append → Clone-server 트랙만 본 저장소에 없다. sibling fork(Clone Glasses)가 담당한다. 자세한 분기 사유는 [03. project_architecture.md §5](./03.%20project_architecture.md) 참고.

## 2. 트랙 구성

| 트랙 | ingestType | 담당 |
| --- | --- | --- |
| RTMP live (glasses → Android → MediaMTX) | `MEDIAMTX` | 본 저장소 (`:transport-rtmp`) |
| WHIP live (WebRTC → MediaMTX) | `MEDIAMTX` | 본 저장소 (`:transport-whip`) |
| HTTP-chunk live upload (fMP4 → EgoFlow backend) | `HTTP` | 본 저장소 (`:transport-http`) |
| slab-append → Clone server | — | sibling fork: Clone Glasses |

세 transport 모두 같은 `Transport` seam과 `EgoFlowBackendClient` 제어면을 공유한다. WHIP은 별도 ingest type이 아니라 MediaMTX ingest를 RTMP와 공유하며 publish 단계만 다르다.

## 3. 샘플 맵

| 경로 | 역할 | 상태 |
| --- | --- | --- |
| `samples/CameraAccessAndroid` | DAT 기반 Android live preview + RTMP/WHIP/HTTP publish | 현재 기준 구현 (server-integrated) |
| `samples/CameraAccess` | iOS DAT 샘플 (glasses/iPhone preview + photo, Gemini Live + OpenClaw 어시스턴트) | reference-only, work in progress — server flow 미연동 |

RTMP/WHIP를 받는 MediaMTX 스택은 **외부 참조 스택**이며 더 이상 저장소에 vendoring 되지 않는다.

`CameraAccessAndroid`는 다섯 개의 Gradle 모듈로 분리되어 있다 (`:app`, `:core`, `:transport-rtmp`, `:transport-whip`, `:transport-http`). 자세한 모듈 경계는 [03. project_architecture.md §2](./03.%20project_architecture.md) 참고.

## 4. 기술 스택

### 4.1 Android (`CameraAccessAndroid`)

| 영역 | 구현 |
| --- | --- |
| Platform | Android (`compileSdk 35`, `minSdk 31`, `targetSdk 34`) |
| Language | Kotlin (`2.1.20`), AGP `8.6.0`, JDK 17 |
| Build | Gradle multi-module (`:app`, `:core`, `:transport-rtmp`, `:transport-whip`, `:transport-http`) |
| UI | Jetpack Compose, `compose-icons-lucide` 아이콘 |
| Glasses SDK | Meta Wearables DAT Android SDK (GitHub Packages, `read:packages` PAT 필요) |
| Transport seam | `:core`의 `Transport` 인터페이스 |
| Streaming | RTMP/RTMPS publish · WHIP(WebRTC) publish · HTTP fMP4 chunk 업로드 |
| Backend HTTP | OkHttp (`EgoFlowBackendClient`: login/repositories/register/publish-ticket/close-intent/http-streams) |
| Encoding | MediaCodec (H.264/HEVC, `:core/encoder/VideoEncoder`) |

### 4.2 외부 ingest 스택

RTMP/WHIP는 외부 MediaMTX host로 나간다. HTTP transport는 EgoFlow backend의 `/http-streams` 제어면으로 직접 업로드한다. 어느 쪽이든 앱의 backend base URL만 테스트 대상 host로 맞추면 된다.

## 5. 중요한 구분

- `CameraAccessAndroid`는 현재 기준 Android 구현이다. RTMP / WHIP / HTTP 세 transport를 지원한다.
- RTMP/WHIP ingest(MediaMTX)는 production EgoFlow server와 별개의 외부 스택이다.
- slab-append/Clone-server 트랙은 본 저장소에 없다. sibling fork(Clone Glasses)에서 진행된다.
